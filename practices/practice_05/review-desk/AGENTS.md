# Правила проекта для агента

Review Desk: FastAPI-приложение, где ментор выдаёт задачи, ученики сдают решения, ментор их ревьюит.

## Источники
- Существующее поведение: `docs/baseline.md` и тесты. Его нельзя
  ломать; менять только если это прямо записано в спецификации фичи.
- Новая фича: только принятая спецификация этой фичи - OpenSpec
  (`openspec/changes/<name>/`, после archive `openspec/specs/`)
  или Spec Kit (`specs/<feature>/`). Реализуй только то, что там
  описано.
- Архитектура, модель данных, страницы: `docs/architecture.md`.
  Структуру слоёв не меняй без согласования.

## Архитектура
- Бизнес-правила (права, статусы, валидация) только в `app/services/`. Роуты в `app/web/` разбирают запрос, вызывают сервис и рендерят ответ.
- Шаблоны Jinja2 с автоэкранированием; `|safe` не использовать.
- Без JS-фреймворков и сборки фронтенда.

## Проверка
- Единственная команда проверки: `sh scripts/check.sh`. Задача не готова, пока она не выводит `CHECK: PASS`.
- Каждый критерий приёмки покрыт тестом. Тесты baseline
  называются `test_usN_acM_...`; тесты фичи лежат в
  `tests/test_<feature>.py` и в имени или docstring ссылаются
  на требование из спецификации.

## Процесс
- Сначала тест, показать его падение, затем минимальная реализация.
- Если требование неоднозначно или противоречит архитектуре — остановись и спроси, не додумывай.

## Нельзя без явного поручения
- Менять `docs/baseline.md` и `scripts/check.sh`.
- Удалять или ослаблять существующие тесты ради зелёного результата.
- Добавлять зависимости сверх `requirements.txt`.
- Делать `git commit` и `git push`.
