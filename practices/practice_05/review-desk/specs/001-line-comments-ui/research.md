# Research: построчные комментарии, интерфейс

Все неизвестные закрыты решениями ниже; открытых вопросов не осталось.

## R-1. Как ментор выбирает строку без JS
- **Decision**: одна форма «номер строки + текст» под кодом (LC-18). Номер вводится в поле `line` (`inputmode="numeric"`), строки кода имеют `id="L{n}"`, редирект после успеха ведёт на `#L{n}`.
- **Rationale**: FR-002, SC-001 (три действия: номер, текст, отправить). Нет числового GET-параметра, его разбора и состояния «форма открыта у строки N»; одна форма вместо ссылки на каждой строке кода до 100 000 символов.
- **Alternatives**: ссылка «Комментировать» у каждой строки с GET-параметром выбора строки и формой под строкой (отдельный разбор параметра и тесты, два состояния страницы); `<details>` на каждой строке (N форм на странице).

## R-2. Разметка кода с комментариями
- **Decision**: вместо одного `<pre>` - блок `div.code` из строк-контейнеров `div.code-row#L{n}`: внутри `span.line-no` (номер текстом) и `code.line-text` (с `white-space: pre`); под ним `div.line-comments`. Номера берутся из `loop.index` по списку `code_lines` из контекста (LC-04, LC-11); шаблон код сам не делит.
- **Rationale**: комментарии не могут жить внутри `<pre>` без поломки вёрстки; явные номера проверяемы в тестах (CSS-счётчик нет); нумерация приходит из сервиса, поэтому у ментора, ученика и валидатора номера совпадают (в том числе для кода с `\r`).
- **Alternatives**: оставить `<pre>` с CSS-счётчиком и вставлять комментарии таблицей после блока (теряется «под строкой»); `<table>` (семантичнее, но тяжелее стилизовать перенос/прокрутку).

## R-3. Очень длинные строки
- **Decision**: у `code-text` `white-space: pre`, контейнер `div.code` с `overflow-x: auto`; комментарии и форма вне прокручиваемой полосы строки шириной контейнера, текст комментария с `white-space: pre-wrap; overflow-wrap: anywhere`.
- **Rationale**: Edge Cases спеки - вёрстка не ломается; прежнее поведение `pre.code` (горизонтальная прокрутка) сохраняется.

## R-4. Ошибки и повторное открытие формы
- **Decision**: `POST` при `ValidationError` рендерит страницу сдачи со статусом `400` с ключами `line_comment_errors` и `line_comment_form` (LC-11, LC-16). Ошибки `line` и `text` выводятся у своих полей через `_field_error.html`; введённые номер и текст возвращаются в форму всегда.
- **Rationale**: FR-012, FR-013 (clarify: `400`, текст не теряется). Номер вводится вручную, поэтому ошибка номера - обычный сценарий, а не подделка запроса.
- **Alternatives**: редирект с flash через сессию (в проекте нет flash; расходится с остальными формами).

## R-5. Статус `403` для ученика и порядок проверок
- **Decision**: POST-маршрут использует `Depends(require_mentor)`, как `POST /submissions/{id}/review`; `Forbidden` и `NotFound` переводятся существующим обработчиком (`app/main.py`).
- **Rationale**: FR-010 - любой ученик получает `403`, в том числе на несуществующий id (так же ведёт себя ревью); неавторизованный перенаправляется на `/login` (baseline US-1 AC3).

## R-6. id вне диапазона `INTEGER`
- **Decision**: проверка `submission_id` делается в сервисе через `fits_sqlite_int` (как `create_review`, LC-08); роут принимает `submission_id: int` без собственной проверки. Для `line` `fits_sqlite_int` не нужна (LC-15).
- **Rationale**: `openspec/specs/path-id-bounds`; бизнес-правила не в `web/`.

## R-7. Фильтр очереди
- **Decision**: `assignment_id` (строка) принимается формой и `GET`-параметром и обрабатывается `review_service.queue_filter_or_none`; после успеха редирект `303` на `/submissions/{id}?assignment_id=K#L{n}` (LC-10), ссылка «← Очередь ревью» ведёт на очередь с тем же фильтром, в том числе после `400` (LC-13).
- **Rationale**: US-1 AC5, FR-016. Мягкий фильтр не ломает страницу при мусоре.

## R-8. Дополнительное: пустое состояние
- **Decision**: если комментариев нет, над кодом плашка «Комментариев к строкам пока нет» (`p.muted#no-line-comments`); сама вёрстка кода не меняется (FR-011).

## R-9. Новая попытка
- **Decision**: комментарии привязаны к `Submission`; страница новой попытки показывает пустое состояние, страница прошлой - свои комментарии (LC-22, FR-019). Тест двух попыток одной задачи.
- **Rationale**: новая попытка - новая сдача с другим кодом, перенос не определим.

## R-10. Двойная отправка и CSRF
- **Decision**: не вводятся (спека, Assumptions). После `303` повторная отправка обновлением не создаёт дубль (FR-005).
