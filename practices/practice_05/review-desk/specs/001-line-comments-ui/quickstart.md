# Quickstart: проверка интерфейса построчных комментариев

Предпосылки: логика реализована по [общему контракту](../line-comments-contract.md) (LC-28); пользователи созданы по
`docs/architecture.md` (раздел «Запуск»).

## Автоматически
```bash
sh scripts/check.sh      # ожидается CHECK: PASS
```
Тесты фичи: `tests/test_line_comments_ui.py` (по одному на FR/сценарий; docstring со ссылкой на `LC-NN` и `[UI FR-nnn]`).

## Вручную (без JavaScript)
1. Ученик `alice` сдаёт код из 3+ строк (с пустой строкой и `<script>`), ментор `mentor` открывает сдачу: у каждой строки номер, под кодом одна форма «номер + текст», ссылок «Комментировать» нет (US-1 AC1-2).
2. Ввести номер 2 и текст, отправить: редирект на `#L2`, комментарий под строкой 2 с автором и датой (US-1 AC3).
3. Повторить для строки 2: два комментария, старый выше (US-1 AC4).
4. Открыть сдачу из `/review?assignment_id=K`, оставить комментарий: `Location` содержит `?assignment_id=K#L2`, «← Очередь ревью» ведёт на `/review?assignment_id=K` (US-1 AC5).
5. Отправить пустой текст: `400`, ошибка у поля текста, номер и текст в форме сохранены (US-3 AC2). Слишком длинный текст: ввод сохранён (AC3).
6. Номер `99` при 3 строках или `05`, текст `x`: `400`, ошибка у поля номера, текст `x` в форме (AC4). `curl -b <cookie> -d line=1 -d text=x .../submissions/99999999999999999999/line-comments`: `404` (AC5).
7. Второй ментор открывает сдачу: видит комментарии обоих менторов с именами (US-1 AC7).
8. Войти `alice`: комментарии под нужными строками, без формы (US-2 AC1-2); POST от ученика: `403` (AC4); чужая сдача: `404` (AC3); `<script>` показан текстом (AC5).
9. `alice` сдаёт вторую попытку (после ревью `changes_requested`): страница второй попытки с пустым состоянием, страница первой - со своими комментариями (US-2 AC6).
10. Сдача без комментариев: плашка «Комментариев к строкам пока нет» (US-3 AC1). Сдача с ревью: форма остаётся у ментора (FR-003).
