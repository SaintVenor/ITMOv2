# Research: построчные комментарии (логика)

Неясностей из Technical Context нет. Ниже решения и допущения плана (по Принципу V конституции).

## Решения

### R1. Хранение — одна новая таблица `line_comments`
- **Decision**: класс `LineComment` в `app/models.py`, таблица создаётся уже существующим `create_all` в `init_db`.
- **Rationale**: FR-002 и бриф запрещают менять существующие таблицы; `create_all` добавляет только отсутствующие таблицы, поэтому уже созданная БД работает без миграций.
- **Alternatives**: колонка в `submissions`/`reviews` (ломает созданную БД, отвергнуто); JSON-поле в `reviews` (ревью одно на сдачу, а комментариев много, и ревью может не быть).

### R2. Определение строки — `split_code_lines`
- **Decision**: единственная функция `split_code_lines(code)` (LC-04): `\r\n` и `\r` → `\n`, `split("\n")`, финальный пустой элемент отбрасывается, пустой код → `[]`; `line_count = len(split_code_lines(code))` (LC-05), допустимы номера `1..N`. Шаблон получает `code_lines` из контекста и сам не делит.
- **Rationale**: `clean_text` при сохранении нормализует только `\r\n` (`app/services/validation.py:3`), одиночный `\r` остаётся; браузер показывает его как перенос, а простое разбиение по `\n` — нет, и номера у ментора и ученика разошлись бы. Одна функция для рендера и валидации исключает двойной подсчёт (FR-003). Пустые строки считаются.
- **Alternatives**: встроенное построчное разбиение строки Python не используется: оно делит и по управляющим символам вроде `\x0c`, номера разошлись бы с показом.

### R3. Разбор номера строки — строка, а не `int` в сигнатуре роута
- **Decision**: форма принимает `line: str = Form("")`; сервис принимает `str`, проверяет `re.fullmatch(r"[1-9][0-9]*", s, re.ASCII)`, затем сравнивает с числом строк.
- **Rationale**: `int` в сигнатуре FastAPI превратил бы `05`, `+3`, ` 3` в 422/404 или принял бы их; FR-005 требует каноничный вид и ошибку у поля `line`. Явный `[0-9]` вместо `\d` (как в `reviews._CANONICAL_ID`) отсекает «٣»; используется `fullmatch`, а не `$` (`$` пропускает завершающий `\n`). Перед `int()` длина строки ограничивается 19 символами: больше цифр, чем у 2^63-1, заведомо вне диапазона (и защита от лимита `int()` на 4 300 цифр, из-за которого был бы 500).
- **Alternatives**: `int()` с `try/except` (`int()` принимает `05`, `+3`, ` 3` и `٣` — нарушает FR-005).

### R4. Порядок проверок: роль → сдача → ввод
- **Decision**: в роуте `Depends(require_mentor)` (даёт 403 для ученика раньше разбора формы; аноним перенаправляется middleware); в сервисе `ensure_role` → поиск сдачи (`NotFound`) → валидация `line` и `text` вместе (одно `ValidationError` с обоими полями).
- **Rationale**: FR-012 (права раньше валидации), FR-011 (`NotFound` для несуществующей сдачи), по образцу `reviews.create_review`.
- **Alternatives**: валидация до поиска сдачи (нельзя проверить диапазон строк без сдачи).

### R5. Текст — `clean_text(..., LINE_COMMENT_MAX, "Комментарий к строке")`
- **Decision**: переиспользовать `app.services.validation.clean_text`; константа `LINE_COMMENT_MAX = 2_000` в новом сервисе (имя `COMMENT_MAX` занято ревью, `app/services/reviews.py:13`), метка «Комментарий к строке» отличает ошибку от поля ревью (LC-06).
- **Rationale**: FR-006, FR-013: нормализация `\r\n`, strip, сообщение «не длиннее N символов (сейчас M)» как у остальных полей. Содержимое не санитизируется.

### R6. Чтение — через `get_submission_for`
- **Decision**: `list_line_comments(db, user, submission_id)` вызывает существующий `submissions.get_submission_for`: ментор видит любую сдачу, ученик только свою, чужая и вне диапазона id — `NotFound`.
- **Rationale**: FR-009…FR-011, повторное использование без копирования правил. Статус сдачи и наличие ревью не проверяются (FR-016, FR-017).

### R7. Порядок списка
- **Decision**: `ORDER BY line ASC, created_at ASC, id ASC` (FR-008). Индекс `(submission_id, line, created_at, id)`.
- **Rationale**: детерминированный порядок при равных временах; один запрос на список.

### R8. Атомарность и конкурентность
- **Decision**: один `db.add` + один `commit`, при исключении `rollback`. Уникальных ограничений на (сдача, строка) нет.
- **Rationale**: FR-007, FR-014: несколько комментариев к строке допустимы, параллельные вставки не конфликтуют; валидация идёт до `add`, поэтому частичных записей нет. Ревью и статус сдачи не трогаются (FR-015).

### R9. Автор — отображаемое имя через связь
- **Decision**: в ответе автор = `author.display_name` (связь `LineComment.author` → `User`); список грузится с `joinedload(LineComment.author)`.
- **Rationale**: FR-008; не раскрывать `username` и `password_hash`.

## Допущения плана

- **A1. Общий контракт главнее.** Интерфейс сервиса, маршрут, ключи контекста и ошибки заданы `specs/line-comments-contract.md` (LC-07…LC-17); `contracts/line-comments.md` ссылается на него. Шаблон страницы сдачи правит команда UI (LC-27).
- **A2. Маршрут**: `POST /submissions/{submission_id}/line-comments` (форма `line`, `text`, необязательный `assignment_id`; успех — `303` на `/submissions/{id}[?assignment_id=K]#L{n}`, LC-09, LC-10). Имя отделяет сущность от `Review.comment`. Отдельного маршрута чтения нет: данные отдаёт `list_line_comments` на странице сдачи.
- **A3. Ошибка валидации в форме**: `400` и повторный показ страницы сдачи (`render_submission`) с `line_comment_errors` (`{"line": ..., "text": ...}`) и `line_comment_form` (введённые значения обоих полей всегда); `queue_filter` из `queue_filter_or_none` (LC-13, LC-16). Тексты: номер — «Номер строки: целое от 1 до {N}» (при N = 0 — «В коде нет строк»), текст — из `clean_text`.
- **A4. `render_submission` загружает комментарии сам** (LC-12): добавляются `db` и новые аргументы только keyword-only в конец сигнатуры; функция вызывается позиционно из `app/web/review.py:54-63`, поэтому после неудачного ревью страница показывает комментарии и не пишет, что их нет. Ключи контекста — LC-11.
- **A5. Коды ответов** следуют существующим: 404/403/400 (`ERROR_STATUS` в `app/main.py`); `Conflict` (409) в этой фиче не используется.
- **A6. Время создания** — `utcnow()` из `app/models.py`, тот же формат, что у `Review.created_at`.
- **A7. Сдача в пути с нечисловым id** (`/submissions/abc/line-comments`) — 404 через существующий обработчик `RequestValidationError`; тест проверяет статус и заголовок «Не найдено», текст `message` не проверяется (LC-17).
- **A8. Фильтр очереди**: `assignment_id: str | None = Form(None)` и `queue_filter_or_none` для редиректа и 400-перерисовки (LC-13).
