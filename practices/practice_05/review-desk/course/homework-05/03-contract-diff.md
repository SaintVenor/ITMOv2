# 03. Сверка спек UI и логики: материал для общего контракта

Фича: построчные комментарии ментора к коду сдачи (Spec Kit). Сравниваются две независимо написанные
спеки с планами. Контракт здесь не пишется, спеки и код не меняются.

**Сокращения.** `UI` = `specs/001-line-comments-ui/`, `Л` = `specs/002-line-comments-logic/`.
Ссылки вида `UI spec:148` = файл `spec.md` строка 148; `UI research`, `UI plan`, `UI data-model`,
`UI routes` (`contracts/ui-routes.md`), `UI svc` (`contracts/service-expectations.md`);
`Л contract` = `contracts/line-comments.md`. Clarify: `team-ui/clarify-answers.md`,
`team-logic/clarify-answers.md` (в `course/homework-05/`). Код проверен на диске, пути даны от корня
`review-desk/`.

**Что проверено запуском** (только чтение, ничего не менялось): `clean_text('a\r\nb\rc\r\n\n')`
возвращает `'a\nb\rc'`; `int('9'*5000)` падает `ValueError` (лимит 4300 цифр); `int()` принимает
`'٣'`, `' 5'`, `'+5'`, `'05'`, `'1_000'`; `'a\x0cb c'.splitlines()` даёт 3 элемента;
`re.fullmatch(r'[1-9][0-9]*', '5\n', re.ASCII)` не совпадает.

### Решение 1. Что такое «строка кода» и кто её считает (строки: Д1, Д2, К1, К2)
- **Вопрос:** одна функция в `services` для рендера и для валидации, и по каким правилам она режет код?
- **Варианты:**
  - A (UI): шаблон делит `code.split("\n")`, сервис считает `len(code.split("\n"))` отдельно, хвостовой `\n` даёт пустую строку.
  - B (Л): `line_count` в сервисе, шаблон делит сам, `\r` не обрабатывается.
  - C (заказчик): `split_code_lines(code)` в `app/services/line_comments.py`: `\r\n` и `\r` → `\n`, `split("\n")`, один финальный пустой элемент отбрасывается (пустой код → `[]`). `line_count = len(split_code_lines(code))`. Шаблон получает `code_lines` из контекста и сам не делит.
- **Рекомендация:** C. `clean_text` нормализует только `\r\n` (`validation.py:3`, проверено), одиночный `\r` остаётся, браузер покажет его как перенос, а `split("\n")` нет — номера у ментора и ученика разойдутся. Хвостового `\n` в сохранённом коде нет (`strip`), но функция обязана быть корректной и без этой гарантии. `splitlines()` не использовать (режет по `\x0c`, ` `). Проверяемо тестами функции: `""→[]`, `"a\n"→["a"]`, `"a\r\nb\rc"→["a","b","c"]`, `"a\x0cb c"→["a\x0cb c"]`; страничным: код с `\r` рендерится и нумеруется теми же строками, что принимает валидатор. Побочное изменение: показ кода с одиночным `\r` (baseline его не описывает, тест CR только `tests/test_us3_submissions.py:152` про `\r\n`).
- **Цена альтернативы:** при A/B комментарий «к строке 3» может указывать на другую строку у ученика, чем у ментора; двойной подсчёт разойдётся при любом будущем изменении одной из сторон.
- **Что меняется:**
