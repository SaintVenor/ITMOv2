# Data Model (вид данных для UI): построчные комментарии

Таблицу, ограничения и миграцию `create_all` определяет команда логики (бриф: только новая таблица, существующие не
меняются). Здесь - то, что UI читает и передаёт; поля соответствуют Key Entities спеки.

## LineComment (читает UI)

| Поле | Тип | Использование в UI |
|---|---|---|
| `id` | int | id элемента `comment-<id>` для якорей/тестов |
| `submission_id` | int | привязка к странице сдачи |
| `line_number` | int (≥ 1) | группировка под строкой |
| `text` | str | вывод с автоэкранированием, `white-space: pre-wrap` |
| `author` | User (`display_name`) | «Автор · дата» |
| `created_at` | datetime | фильтр `dt` (UTC) |

Порядок: по `created_at`, затем `id` (старый выше) - обеспечивает сервис (FR-006).

## Данные страницы сдачи (контекст шаблона)

| Ключ | Откуда | Назначение |
|---|---|---|
| `submission` | существующий `get_submission_for` | как сейчас |
| `comments_by_line` | `dict[int, list[LineComment]]`, собирается в `web/` из упорядоченного списка сервиса | вывод под строками |
| `has_comments` | `bool(comments_by_line)` | пустое состояние (FR-011) |
| `can_comment` | `line_comment_service.can_comment(user, submission)` | показ действий «Комментировать» (FR-002, FR-008) |
| `open_line` | `int \| None` из `?line=` / POST | какая строка с формой и выделением |
| `draft_text` | `str` | сохранённый ввод при ошибке (FR-012) |
| `errors` | `dict[str, str]` | `text`, `line` |

## Связи и жизненный цикл

- Сдача 1 - N комментариев. Комментарий создаётся только ментором и далее не меняется (редактирования и удаления нет).
- Статус сдачи и ревью комментарий не затрагивает (FR-003, clarify Q1); видимость ученику не зависит от статуса (FR-017).
- Нумерация строк: `submission.code.split("\n")`, с 1; число строк = `len(...)`. Для рендера `line_count` UI не хранит.
