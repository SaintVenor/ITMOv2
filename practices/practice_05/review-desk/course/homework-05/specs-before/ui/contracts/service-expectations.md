# Что UI ожидает от команды логики

Предлагаемый интерфейс модуля `app/services/line_comments.py`. Контракта `specs/line-comments-contract.md` на момент
плана нет (A-1); при расхождении с ним правится этот документ.

## Функции

| Функция | Поведение |
|---|---|
| `list_comments(db, submission) -> list[LineComment]` | комментарии сдачи по `created_at`, затем `id`; `author` доступен |
| `can_comment(user, submission) -> bool` | `True` для любого `mentor`, в любом статусе сдачи (FR-003); `False` для ученика |
| `create_comment(db, mentor, submission_id, line_raw, text) -> LineComment` | см. ниже |
| `parse_open_line(submission, raw) -> int \| None` | мягко: валидный номер в диапазоне или `None` (для `?line=`), без исключений |

`create_comment` принимает `line_raw` строкой и сам разбирает её; роут не парсит число.

## Исключения (из `app/services/errors.py`)

| Исключение | Когда | Как UI показывает |
|---|---|---|
| `Forbidden` | вызывающий - не ментор | `403` (уже делает `require_mentor`) |
| `NotFound` | нет сдачи или id вне `INTEGER` (`fits_sqlite_int`) | `404` |
| `ValidationError({"text": ...})` | текст пуст после обрезки или длиннее предела (ожидается 5 000, как `COMMENT_MAX`) | `400`, ошибка у поля |
| `ValidationError({"line": ...})` | номер не число или вне `1..число строк` | `400`, баннер |

Сообщения - на русском, готовые к показу (как у остальных сервисов). Число строк определяется как `len(code.split("\n"))`,
то же, что считает шаблон.

## Чего UI не делает и не требует

- Не хранит и не фильтрует комментарии по статусу сдачи: ученик-автор получает все комментарии сдачи сразу (FR-017).
- Не проверяет права и диапазон строк самостоятельно (только показывает `can_comment`).
- Не ожидает правок существующих таблиц; чужая сдача для ученика остаётся `NotFound` из `get_submission_for`.

## Зависимость порядка работ

Роут и шаблоны можно писать после того, как логика отдаёт эти функции (или заглушку с тем же интерфейсом); тесты UI
используют настоящий сервис.
