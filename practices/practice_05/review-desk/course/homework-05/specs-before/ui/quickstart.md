# Quickstart: проверка интерфейса построчных комментариев

Предпосылки: интерфейс сервиса из [contracts/service-expectations.md](contracts/service-expectations.md) реализован; пользователи созданы по `docs/architecture.md` (раздел «Запуск»).

## Автоматически
```bash
sh scripts/check.sh      # ожидается CHECK: PASS
```
Тесты фичи: `tests/test_line_comments_ui.py` (по одному на FR/сценарий; ссылка на `FR-NNN` в имени или docstring).

## Вручную (без JavaScript)
1. Ученик `alice` сдаёт код из 3+ строк (с пустой строкой и `<script>`), ментор `mentor` открывает сдачу: у каждой строки номер и «Комментировать» (US-1 AC1).
2. Нажать «Комментировать» у строки 2: URL содержит `?line=2`, под строкой форма, строка выделена (US-1 AC2).
3. Отправить текст: страница сдачи, комментарий под строкой 2 с автором и датой, форма закрыта (US-1 AC3; редирект `303`).
4. Повторить для строки 2: два комментария, старый выше (US-1 AC4).
5. Открыть сдачу из `/review?assignment_id=K`, оставить комментарий: «← Очередь ревью» ведёт на `/review?assignment_id=K` (US-1 AC5).
6. Отправить пустой текст: `400`, ошибка у поля, форма у той же строки (US-3 AC2). Слишком длинный текст: ввод сохранён (AC3).
7. Выполнить `curl -b <cookie> -d line=999 -d text=x .../submissions/<id>/line-comments`: `400` и баннер ошибки (AC4); для `id=99999999999999999999`: `404` (AC5).
8. Войти `alice`: комментарии под нужными строками, без «Комментировать» и форм (US-2 AC1-2); POST от ученика: `403` (AC4); чужая сдача: `404` (AC3); `<script>` показан текстом (AC5).
9. Сдача без комментариев: плашка «Комментариев к строкам пока нет» (US-3 AC1). Сдача с ревью: «Комментировать» остаётся у ментора (FR-003).
