# Research: построчные комментарии, интерфейс

Все неизвестные закрыты решениями ниже; `NEEDS CLARIFICATION` не осталось.

## R-1. Как ментор выбирает строку без JS
- **Decision**: ссылка «Комментировать» у строки ведёт на `GET /submissions/{id}?line=N[&assignment_id=K]#line-N`. Страница открывает форму под строкой N и выделяет строку.
- **Rationale**: FR-002, US-1 AC2: «страница обновилась». Ссылка не меняет состояние, работает без JS, повторяет приём `?assignment_id=` из очереди ревью.
- **Alternatives**: `<details>` на каждой строке (форма уже в DOM; N форм на странице, тяжело для кода на тысячи строк, нет серверного «выделения»); кнопка-форма `POST` для выбора строки (лишний POST без изменения данных).

## R-2. Разметка кода с комментариями
- **Decision**: вместо одного `<pre>` - блок `div.code` из строк-контейнеров `div.code-row#line-N`: внутри `span.line-no` (номер текстом), `code.line-text` (с `white-space: pre`), действие «Комментировать» (только ментору); под ним `div.line-comments` и форма. Номера берутся из `loop.index` по `code.split("\n")`.
- **Rationale**: комментарии и форма не могут жить внутри `<pre>` без поломки вёрстки; явные номера проверяемы в тестах (CSS-счётчик нет); нумерация по `split("\n")` совпадает с baseline и с допущением спеки (завершающий перевод строки даёт последнюю пустую строку с номером).
- **Alternatives**: оставить `<pre>` с CSS-счётчиком и вставлять комментарии таблицей после блока (теряется «под строкой»); `<table>` (семантичнее, но тяжелее стилизовать перенос/прокрутку).

## R-3. Очень длинные строки
- **Decision**: у `code-text` `white-space: pre`, контейнер `div.code` с `overflow-x: auto`; комментарии и форма вне прокручиваемой полосы строки шириной контейнера, текст комментария с `white-space: pre-wrap; overflow-wrap: anywhere`.
- **Rationale**: Edge Cases спеки - вёрстка не ломается; прежнее поведение `pre.code` (горизонтальная прокрутка) сохраняется.

## R-4. Ошибки и повторное открытие формы
- **Decision**: `POST` при `ValidationError` рендерит страницу сдачи со статусом `400`, `open_line` = введённый номер (если он валиден), `draft_text` = введённый текст, `errors` из исключения. Ключи: `text` - у поля, `line` - общий баннер. Если номер невалиден, форма не открывается и введённый текст не восстанавливается (допущение: такое возможно только при подделке запроса в обход UI).
- **Rationale**: FR-012, FR-013 (подтверждено clarify: `400`, текст сохраняется там, где форма есть). Невалидный номер возможен только при подделке запроса.
- **Alternatives**: редирект с flash через сессию (в проекте нет flash; расходится с остальными формами).

## R-5. Статус `403` для ученика и порядок проверок
- **Decision**: POST-маршрут использует `Depends(require_mentor)`, как `POST /submissions/{id}/review`; `Forbidden` и `NotFound` переводятся существующим обработчиком (`app/main.py`).
- **Rationale**: FR-010 - любой ученик получает `403`, в том числе на несуществующий id (так же ведёт себя ревью); неавторизованный перенаправляется на `/login` (baseline US-1 AC3).

## R-6. id вне диапазона `INTEGER`
- **Decision**: проверка делается в сервисе через `fits_sqlite_int` (как `create_review`); роут принимает `submission_id: int` без собственной проверки.
- **Rationale**: `openspec/specs/path-id-bounds`; бизнес-правила не в `web/`.

## R-7. Фильтр очереди
- **Decision**: `assignment_id` (строка) принимается формой и `GET`-параметром и обрабатывается `review_service.queue_filter_or_none`; после успеха редирект `303` на `/submissions/{id}?assignment_id=K#line-N`, ссылка «← Очередь ревью» остаётся прежней (`review_queue_url`).
- **Rationale**: US-1 AC5, FR-016. Мягкий фильтр не ломает страницу при мусоре.

## R-8. Дополнительное: пустое состояние
- **Decision**: если комментариев нет, над кодом плашка «Комментариев к строкам пока нет» (`p.muted#no-line-comments`); сама вёрстка кода не меняется (FR-011).

## R-9. Двойная отправка и CSRF
- **Decision**: не вводятся (спека, Assumptions). После `303` повторная отправка обновлением не создаёт дубль (FR-005).
