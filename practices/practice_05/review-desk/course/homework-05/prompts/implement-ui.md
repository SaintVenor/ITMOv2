Правила (AGENTS.md и контракт):
- Jinja2 с автоэкранированием, `|safe` не использовать; без JS, без сборки фронтенда.
- Строки кода выводятся из `code_lines` контекста (LC-04), шаблон сам код не делит;
  у каждой строки видимый номер и `id="L{n}"`; комментарии под своей строкой.
- Одна форма комментария под кодом, только у ментора (`can_comment`): поле `line`, `textarea name=text`
  с `maxlength` из `line_comment_max`, скрытое `assignment_id` при фильтре очереди; значения и ошибки
  из `line_comment_form` / `line_comment_errors` через `_field_error.html`.
- Существующие тесты не менять и не ослаблять: показ кода, экранирование (US-5 AC3), форма ревью
  и очередь должны остаться зелёными без правок.
- Новые зависимости не добавлять. `docs/baseline.md`, `scripts/check.sh`, `AGENTS.md` не менять.
- Тесты в `tests/test_line_comments_ui.py`; docstring каждого теста начинается с `[UI FR-nnn]` и
  содержит `LC-nn` (LC-29).

Ловушки проекта, учесть в тестах:
- POST-тест без валидного тела формы даёт ложный 404/400: в каждом POST-тесте полное тело формы
  и проверка, что ошибка именно та.
- Тексты 404 у разных обработчиков разные: проверяются статус и заголовок «Не найдено», не текст.
- Проверки HTML - по устойчивым признакам (`id="L3"`, `data-field="line"`, `name="text"`,
  `maxlength="2000"`), а не по целым кускам разметки.

## Шаг 4. Сквозной тест `tests/test_line_comments_e2e.py`

Через `fastapi.testclient` и настоящие роуты, docstring `[UI FR-nnn] [Л FR-nnn] LC-nn`:
1. ментор оставляет комментарий к строке 2 → `303` на `#L2` → ученик-автор на странице своей
   сдачи видит текст под строкой 2 (экранированный: текст с `<b>` показан как текст);
2. граница: строка `N+1` и номер вне int64 (`9223372036854775808`) → `400`, комментарий не
   создан, ввод сохранён;
3. ошибка доступа: другой ученик открывает чужую сдачу → `404`, комментариев не видно.
