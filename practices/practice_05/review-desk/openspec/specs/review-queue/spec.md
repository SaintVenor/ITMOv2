# review-queue Specification

## Purpose

Очередь ревью ментора (`/review`) и её фильтрация по задаче. Фильтр сохраняется при переходе к сдаче и после ревью, чтобы ментор мог проверять сдачи одной задачи подряд.

## Requirements

### Requirement: RQF-1 Фильтр очереди по задаче
Ментору на `GET /review` с параметром `assignment_id`, равным id существующей задачи, система SHALL показывать только сдачи этой задачи со статусом `pending`, старые сверху. Без параметра и с пустым значением (`?assignment_id=`) система SHALL показывать полную очередь, как в baseline (US-4 AC1). При повторе параметра система SHALL использовать последнее значение.

#### Scenario: S1 Фильтр показывает только pending-сдачи задачи, старые сверху
- **WHEN** у задачи A две `pending`-сдачи и одна `accepted`, у задачи B одна `pending`-сдача, и ментор открывает `/review?assignment_id=<A>`
- **THEN** ответ `200`, в нём ссылки только на две `pending`-сдачи задачи A, более старая первой

#### Scenario: S2 Без параметра очередь не меняется
- **WHEN** ментор открывает `/review` без параметра
- **THEN** показываются все `pending`-сдачи всех задач, старые сверху, ссылки «Открыть» имеют вид `href="/submissions/<id>"` без query-строки

#### Scenario: S3 Пустое значение означает «без фильтра»
- **WHEN** ментор открывает `/review?assignment_id=`
- **THEN** ответ `200` с полной очередью, как без параметра

#### Scenario: S8 Повтор параметра — последнее значение
- **WHEN** ментор открывает `/review?assignment_id=<A>&assignment_id=<B>`, где A и B существуют
- **THEN** показываются только `pending`-сдачи задачи B

### Requirement: RQF-2 Пустое состояние отфильтрованной очереди
Если задача из фильтра существует, но `pending`-сдач по ней нет, система SHALL показывать текст «Нет сдач, ждущих ревью, по задаче <название>» и ссылку «Сбросить фильтр» на `/review` вместо общего текста. Общий текст «Непроверенных сдач нет.» система SHALL показывать только для пустой очереди без фильтра.

#### Scenario: S4 Задача есть, pending-сдач нет
- **WHEN** у задачи A нет `pending`-сдач (а у задачи B есть), и ментор открывает `/review?assignment_id=<A>`
- **THEN** ответ `200`, есть текст «Нет сдач, ждущих ревью, по задаче <название A>» и ссылка «Сбросить фильтр» с `href="/review"`, нет текста «Непроверенных сдач нет.» и нет ссылок на сдачи

#### Scenario: S5 Пустая очередь без фильтра
- **WHEN** `pending`-сдач нет совсем, и ментор открывает `/review`
- **THEN** показан текст «Непроверенных сдач нет.», нет текста «Нет сдач, ждущих ревью, по задаче» и нет ссылки «Сбросить фильтр»

### Requirement: RQF-3 Несуществующая задача в фильтре
Если на `GET /review` значение `assignment_id` записано в допустимом формате, но задачи с таким id нет, система SHALL отвечать `404` со страницей ошибки и сообщением «Задача не найдена», а не ответом `500`. Это касается и предельного значения 2^63-1.

#### Scenario: S6 Несуществующий id
- **WHEN** ментор открывает `/review?assignment_id=9999`, а задачи 9999 нет
- **THEN** ответ `404`, в теле «Задача не найдена»

#### Scenario: S6b Предельное значение 2^63-1
- **WHEN** ментор открывает `/review?assignment_id=9223372036854775807`
- **THEN** ответ `404` с «Задача не найдена», не `500`

### Requirement: RQF-4 Невалидное значение фильтра даёт 404 (изменение поведения)
Допустимый формат `assignment_id` на `GET /review`: только ASCII-цифры без ведущего нуля (`^[1-9][0-9]*$`), значение не больше 2^63-1. Любое другое непустое значение система SHALL отклонять ответом `404` «Задача не найдена», тем же, что для несуществующей задачи, и никогда не отвечать `500`. Раньше такой параметр игнорировался (`200`, полная очередь).

#### Scenario: S7a Нечисловое значение раньше игнорировалось, теперь 404
- **WHEN** ментор открывает `/review?assignment_id=abc`
- **THEN** ответ `404` с «Задача не найдена» (в baseline был `200` с полной очередью)

#### Scenario: S7b Неканоничные и выходящие за предел значения
- **WHEN** ментор открывает `/review` со значением `assignment_id` из списка: `0`, `-1`, `05`, ` 5` (ведущий пробел), `+5`, `5.0`, `1_000`, `1e3`, `٥`, `²`, `9223372036854775808`, `99999999999999999999`, `   ` (только пробелы)
- **THEN** для каждого значения ответ `404` с «Задача не найдена», не `200` и не `500`

### Requirement: RQF-5 Проверка доступа раньше разбора фильтра
Система SHALL проверять сессию и роль раньше значения `assignment_id`. Запрос без сессии SHALL получать редирект на `/login`. Не-ментор SHALL получать `403` на `/review` при любом значении параметра, включая невалидное и несуществующее.

#### Scenario: S9 Студент с любым значением получает 403
- **WHEN** студент открывает `/review?assignment_id=<v>` для `v` из: id существующей задачи, `abc`, `9999`, пустое значение
- **THEN** каждый раз ответ `403`, не `404`

#### Scenario: S10 Аноним перенаправляется на вход
- **WHEN** запрос без сессии открывает `/review?assignment_id=abc`
- **THEN** ответ `303` с `Location: /login`

### Requirement: RQF-6 Форма фильтра и отображение активного фильтра
Страница `/review` SHALL всегда, в том числе при пустой очереди, содержать GET-форму с `action="/review"`. В ней `<select name="assignment_id">`: первый пункт «Все задачи» с `value=""`, далее все задачи. Кнопка формы — «Показать». При активном фильтре его пункт SHALL быть выбран, заголовок SHALL иметь вид «Очередь ревью · <название задачи>», а ссылка «Сбросить фильтр» на `/review` SHALL присутствовать.

#### Scenario: S11a Форма без фильтра
- **WHEN** ментор открывает `/review` (очередь может быть пуста)
- **THEN** есть форма `method="get"` с `action="/review"`, `<select name="assignment_id">` с первым пунктом «Все задачи» `value=""`, который выбран, пункты всех задач с `value="<id>"`, кнопка «Показать»; заголовок «Очередь ревью» без суффикса

#### Scenario: S11b Форма при активном фильтре
- **WHEN** ментор открывает `/review?assignment_id=<A>`, и по задаче A есть `pending`-сдачи
- **THEN** пункт задачи A выбран (`selected`), заголовок «Очередь ревью · <название A>», есть ссылка «Сбросить фильтр» с `href="/review"`

### Requirement: RQF-7 Ссылки «Открыть» переносят фильтр
При активном фильтре ссылка «Открыть» каждой сдачи в очереди SHALL вести на `/submissions/<id>?assignment_id=<N>`. Без фильтра ссылка SHALL оставаться `/submissions/<id>`.

#### Scenario: S12 Ссылки несут фильтр только при активном фильтре
- **WHEN** ментор открывает `/review?assignment_id=<A>`, а затем `/review`
- **THEN** в первом ответе ссылки имеют вид `href="/submissions/<id>?assignment_id=<A>"`, во втором `href="/submissions/<id>"`

### Requirement: RQF-8 Страница сдачи сохраняет фильтр
Если ментор открыл `GET /submissions/<id>?assignment_id=<N>` и N — существующая задача, ссылка «← Очередь ревью» SHALL вести на `/review?assignment_id=<N>`, а форма ревью SHALL содержать скрытое поле `assignment_id` со значением N. Это действует, даже если N не совпадает с задачей сдачи. Невалидное или несуществующее значение система SHALL молча игнорировать (ответ как без параметра). Студенту параметр SHALL не влиять на ответ.

#### Scenario: S13 Валидный фильтр на странице сдачи
- **WHEN** ментор открывает `/submissions/<id>?assignment_id=<A>`
- **THEN** ответ `200`, ссылка «← Очередь ревью» с `href="/review?assignment_id=<A>"`, в форме ревью `<input type="hidden" name="assignment_id" value="<A>">`

#### Scenario: S13b Фильтр по другой задаче сохраняется
- **WHEN** ментор открывает сдачу задачи A с `?assignment_id=<B>`, где B существует
- **THEN** ссылка «← Очередь ревью» ведёт на `/review?assignment_id=<B>`, скрытое поле равно B

#### Scenario: S14 Невалидный или несуществующий фильтр игнорируется
- **WHEN** ментор открывает `/submissions/<id>?assignment_id=<v>` для `v` из: `abc`, `0`, `9999`, `99999999999999999999`
- **THEN** ответ `200`, ссылка «← Очередь ревью» с `href="/review"`, скрытого поля `assignment_id` нет

#### Scenario: S14b Без фильтра скрытого поля нет
- **WHEN** ментор открывает `/submissions/<id>` без параметра
- **THEN** ссылка «← Очередь ревью» с `href="/review"`, скрытого поля `assignment_id` нет

#### Scenario: S14c Студенту параметр безразличен
- **WHEN** студент открывает свою сдачу с `?assignment_id=abc` и с `?assignment_id=<A>`
- **THEN** оба ответа `200` и совпадают с ответом без параметра: нет ссылки на очередь и нет формы ревью

### Requirement: RQF-9 Редирект после ревью в отфильтрованную очередь
После успешного `POST /submissions/<id>/review` со скрытым полем `assignment_id`, равным id существующей задачи N, система SHALL отвечать `303` с `Location: /review?assignment_id=<N>`. Если поле отсутствует или пустое, `Location` SHALL быть ровно `/review`.

#### Scenario: S15 Ревью с фильтром
- **WHEN** ментор отправляет валидное ревью с `assignment_id=<A>`
- **THEN** ревью сохранено, ответ `303`, `Location: /review?assignment_id=<A>`

#### Scenario: S16 Ревью без фильтра
- **WHEN** ментор отправляет валидное ревью без поля `assignment_id` или с пустым значением
- **THEN** ревью сохранено, ответ `303`, `Location` ровно `/review`

#### Scenario: S19 Ревью последней pending-сдачи задачи
- **WHEN** ментор ревьюит единственную `pending`-сдачу задачи A с `assignment_id=<A>` и переходит по `Location`
- **THEN** открывается `/review?assignment_id=<A>` с пустым состоянием «Нет сдач, ждущих ревью, по задаче <название A>», пункт A выбран в `<select>`

### Requirement: RQF-10 Невалидный фильтр в POST не мешает ревью и не даёт open redirect
Если скрытое поле `assignment_id` в `POST /submissions/<id>/review` невалидно или указывает на несуществующую задачу, система SHALL сохранить ревью как обычно и ответить `303` с `Location: /review`. `Location` SHALL собираться только из id проверенной задачи. Значение из запроса никогда не попадает в него как есть.

#### Scenario: S17 Невалидные значения скрытого поля
- **WHEN** ментор отправляет валидное ревью с `assignment_id` из: `abc`, `0`, `05`, `9999`, `99999999999999999999`, `//evil.example`, `https://evil.example/`, `/review?x=1`, `1/../../evil`
- **THEN** для каждого значения ревью сохранено, ответ `303`, `Location` ровно `/review`

### Requirement: RQF-11 Ошибка валидации ревью сохраняет фильтр
Если `POST /submissions/<id>/review` с валидным фильтром N отклонён по валидации (US-4 AC2, ответ `400`), страница сдачи SHALL снова содержать скрытое поле `assignment_id=N` и ссылку «← Очередь ревью» на `/review?assignment_id=<N>`. Ответы `409` (повторное ревью) и `404` (нет сдачи) SHALL оставаться прежними страницами ошибки, фильтр в них не переносится.

#### Scenario: S18 Ошибка валидации с фильтром
- **WHEN** ментор отправляет ревью без вердикта с `assignment_id=<A>`
- **THEN** ответ `400` с ошибкой у поля `verdict`, скрытое поле `assignment_id` со значением A, ссылка «← Очередь ревью» с `href="/review?assignment_id=<A>"`

#### Scenario: S18b Повторное ревью с фильтром
- **WHEN** ментор повторно отправляет ревью уже проверенной сдачи с `assignment_id=<A>`
- **THEN** ответ `409`, как в baseline (US-4 AC3)

### Requirement: RQF-12 Экранирование названия задачи
Название задачи SHALL выводиться с экранированием HTML в заголовке активного фильтра, в пустом состоянии отфильтрованной очереди и в пунктах `<select>`.

#### Scenario: S20 Название с HTML
- **WHEN** задача называется `<script>alert(1)</script>`, и ментор открывает `/review?assignment_id=<её id>`
- **THEN** в ответе нет `<script>alert(1)</script>`, есть `&lt;script&gt;alert(1)&lt;/script&gt;` в заголовке, в пустом состоянии и в `<select>`
