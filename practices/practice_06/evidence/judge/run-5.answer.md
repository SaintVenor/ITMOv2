## Пробелы
1. [GET /files, service.py:78-80; sandbox.py:21-29] Нет угрозы на основное поведение: анонимный доступ позволяет читать чужие чеки (user=bob) и служебную записку через traversal внутри Sandbox (path=../../private/operator-note.txt разрешён, т.к. stay-in-root). → Добавить отдельную угрозу (например, T14) класса I/E с предусловием «нет» и последствием «чтение чужих чеков и private/», серьёзность Высокая/Критическая; добавить меры: аутентификация, проверка владельца, запрет выхода за files/{session_user}/ и доступ к private/; добавить тесты (аноним/чужой user → 401/403; path=../../private/... → 403).
2. [POST /orders, service.py:62-73] В таблице мер отсутствует явная мера для T11 (подмена цены): столбец «Мера защиты» пуст, есть только тест. → Явно описать меру (брать цену только из каталога, игнорировать body.price; валидация типа/знака), чтобы соответствовать требованию «у каждой угрозы есть мера».
3. [GET /admin/export, service.py:74-77] Явно занижена серьёзность T13: маршрут без аутентификации по токену выдаёт ПДн всех клиентов при заголовке X-Role от клиента. По шкале в модели это соответствует «Критическая» (анонимный доступ ко всем ПДн), а не «Низкая». → Исправить серьёзность T13 на «Критическая» и приоритизировать меры.
