### Усиление промпта после run-3 (v3)

В run-3 пропущено две порчи из четырёх, поэтому промпт усилен один раз. Общая причина
обоих пропусков: судья засчитывал пункты по таблице маршрутов, диаграмме и мерам
других угроз, а не по наличию строки угрозы. Добавлены общие правила (шаги 2–3
раздела «Как проверять»), без упоминания конкретных маршрутов, ID и порч:

- для каждого маршрута из кода судья сам выводит, что контролирует вызывающий, какие
  проверки отсутствуют и какой актив доступен, и ищет ID угрозы на каждое такое
  наблюдение; упоминание маршрута в таблице или диаграмме покрытием не считается;
- пункты засчитываются только по строкам разделов «Угрозы» и «Меры»; для пунктов 6 и 7
  нужно назвать ID на каждый перечисленный элемент, иначе статус «нет»;
- маршрут покрыт, только если угроза описывает его основное поведение, а не второстепенное.

Результат: находка `GET /files` появилась, L03 по-прежнему пропущена. По условию
run-5 — единственный повтор, дальнейшая подгонка не проводилась.

### Выводы

- Судья надёжно ловит локальные дефекты строки: пустую меру и явно неверную серьёзность.
- Отсутствующие угрозы он находит хуже: удалённую угрозу маршрута — только после
  требования выводить угрозы из кода самостоятельно, удалённую LLM-угрозу из обязательного
  списка — не нашёл ни разу, даже при явном требовании назвать ID на каждый элемент.
  Вероятная причина (гипотеза, не проверялась) — соседние угрозы содержательно близки
  к L03: L05 («решение модели исполняется без проверки схемы и пути»), L06
  (`delete_tree`), L07 (`export_profiles`), и судья засчитывает их как покрытие.
- Вердикт «принято» на настоящей модели (run-1, run-2, run-4) поэтому означает «явных
  дефектов строк нет», но не гарантирует полноту по обязательным LLM-угрозам — их
  наличие в `THREAT_MODEL.md` (L01, L03, L04, L07) проверено вручную.
- Усиленный промпт v3 на настоящей модели не запускался (run-4 выполнен на v2) —

**Надёжен** (стабильно во всех запусках):

- явно неверная серьёзность (P5 — 3 из 3, в т.ч. в run-7 без подсказывающего примера);

**Ненадёжен:**

- удалённая обязательная LLM-угроза «чрезмерные полномочия» не найдена ни разу (0 из 3).
  В run-7 видна причина: судья засчитывает элемент чек-листа по содержательно близким
  угрозам (L05 — непроверенное решение модели, L06 — `delete_tree`), хотя отдельной
  угрозы про избыточный набор инструментов нет. Требование «назвать ID на каждый

- согласованность внутри ответа: найденную порчу P5 он описывает в пробелах, но
  пункт 10 оставляет «да».

**Практический вывод:** вердикту судьи можно доверять для проверки мер, серьёзности
и покрытия маршрутов, но полноту обязательных LLM-угроз нужно проверять вручную
по ID (в `THREAT_MODEL.md` они есть: L01, L03, L04, L07). Промпт дальше не подгонялся,
чтобы не настраивать его под известный пропуск.
