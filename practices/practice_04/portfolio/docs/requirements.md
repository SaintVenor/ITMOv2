# Требования: сайт-портфолио

Сайт рассказывает о разработчике и его проектах. Основной читатель - рекрутер или ревьюер стажировки.

## User stories

| # | История | Статус |
|---|---|---|
| US-1 | Как рекрутер, я вижу на главной странице имя, специализацию, ссылку на GitHub и список проектов. | готово |
| US-2 | Как рекрутер, я фильтрую проекты по технологии (`GET /api/projects?tech=cpp`) и открываю карточку проекта (`GET /api/projects/{slug}`). | готово |
| US-3 | Как рекрутер, я оставляю сообщение через форму связи, а мусорные и спам-запросы отклоняются. | **в работе** |
| US-4 | Как рекрутер, я открываю страницу проекта (`/projects/{slug}`) и фильтрую проекты на главной по технологии. | готово |
| US-5 | Как владелец, я отдаю актуальное резюме в PDF по ссылке. | бэклог |

## Контракт US-3: форма связи

`POST /api/contact`, тело JSON:

| Поле | Тип | Правило |
|---|---|---|
| `name` | string | после `strip()` от 1 до 100 символов |
| `email` | string | содержит ровно один `@`, непустые части до и после него, в части после `@` есть точка |
| `message` | string | после `strip()` от 10 до 2000 символов |
| `website` | string, необязательное | honeypot для ботов: человек его не видит и не заполняет |

Ответы:

- Корректный запрос: `201`, тело `{"status": "received"}`, сообщение сохраняется в памяти процесса (список в модуле приложения).
- Нарушено любое правило полей: `422`, сообщение **не** сохраняется.
- Заполнено поле `website` (непустое после `strip()`): `400`, тело `{"detail": "spam"}`, сообщение **не** сохраняется.

Критерии приёмки:

1. Каждое правило таблицы покрыто тестом, включая граничные длины (1 и 100 для `name`, 10 и 2000 для `message`).
2. Тест проверяет, что отклонённый запрос не попал в хранилище.
3. Существующие тесты не изменены и проходят; `sh scripts/check.sh` выводит `CHECK: PASS`.
