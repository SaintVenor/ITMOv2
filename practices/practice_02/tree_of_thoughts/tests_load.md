# Нагрузочные проверки

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

Нагрузочный тест `POST /api/reviews` сейчас не проводится. Обоснование: эндпоинт синхронно вызывает внешний LLM — `@app.post("/api/reviews")` → `review_service.review(payload["diff"])` → `answer = self.llm.generate(prompt)` (TRAINING_PR.diff:35-37, 19-22), а доступные источники задают для сервиса только функциональные границы: таймаут LLM 10 секунд с контролируемым ответом (CASE.md:66, REL-1) и отклонение diff длиннее 20 000 символов по HTTP 413 (CASE.md:65, API-1). Целевой нагрузки (RPS), квантилей задержки и допустимой доли ошибок для `/api/reviews` в источниках нет, поэтому числа исходной таблицы — 50 rps в течение 60 секунд (допущение), средняя задержка ≤ 500 мс (допущение), ошибки ≤ 1% (допущение) — не были бы ничем, кроме допущений, а прогон с заменой LLM на быстрый мок не отражал бы реальное время ответа, которое определяется LLM-вызовом вплоть до таймаута 10 секунд (CASE.md:66).

Условие, после которого нагрузочный тест понадобится: появится подтверждённое требование к нагрузке (целевой RPS и предел задержки для `POST /api/reviews`) или реальный трафик. Тогда тест будет воспроизводим по коду (TRAINING_PR.diff:35-37) и правилам: профиль задержек LLM задаётся по REL-1 — до 10 секунд, таймаут с контролируемым ответом (CASE.md:66); граница размера diff — по API-1, HTTP 413 (CASE.md:65); измеряться будут время ответа эндпоинта, доля ошибок и доля контролируемых ответов при таймауте — только через request_id, длительность и статус (CASE.md:70, OBS-1: содержимое diff и ответа модели не логируется). Любые числа такого теста без источника помечаются «допущение».
